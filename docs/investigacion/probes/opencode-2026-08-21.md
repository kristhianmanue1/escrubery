# Probe opencode — conversaciones (CE-T1, 2026-08-21)

**Ticket:** CE-T1 del plan `docs/investigacion/Plan_Conversation_Event_v0.md` (issue #2).
**Runner:** `npm run probe:conversacion -- --cli opencode` (backend). **Modo:** read-only sobre
`~/.local/share/opencode/opencode.db` (sqlite, `node:sqlite` con `readOnly: true`). Salida
solo bajo `var/probes/` (gitignored).

## Superficie usada y decisión

- **Superficie:** `almacen_interno` / `opencode.db (sqlite)` / estabilidad `interna`.
- Las superficies *soportadas* candidatas del issue #2 (export JSON, API HTTP, plugins) exigen
  **ejecutar** opencode → excluidas del probe por criterio D1 del plan (artefactos primero;
  ejecución solo con ToS curado). El almacen interno funciona sin ejecutar nada.
- El almacen es un formato interno sin compromiso de estabilidad: **nada aquí se declara
  estable**; el contrato de adaptador (CE-T5) debe registiarlo como riesgo.

## Gate de privacidad (DoD)

Grep de cadenas distintivas de conversaciones reales (`introspeccion_omitida`, `jarvis`,
`keybindingFlavor`, `ESCRUBERY_DOCKER_BIN`) sobre `var/probes/`: **0 matches**. El único
string largo presente es el const del propio contrato (`escrubery/conversation-event/v0`).
Las queries solo seleccionan agregados (`COUNT`, `json_extract` de `role`/`type`/`version`)
— jamás columnas de contenido (`data` de message/part/event solo se filtra, no se proyecta).

## Recomendación para CE-T5 (decisión de adaptadores)

- **Historial:** viable vía almacen interno (con riesgo de formato inestable) o export JSON
  oficial (requiere ejecución → curación ToS). Recomendado: almacen interno para conteos,
  export oficial cuando D1 lo permita, como superficie primaria.
- **Eventos en vivo (prompt/turno/compactación):** la vía soportada son hooks/plugins o la
  API HTTP — ambas exigen ejecución → quedan `pendiente_de_verificar` hasta curación ToS.
- **turno_fallido/turno_interrumpido:** no observables en el almacen; un colector por hooks
  podría capturarlos, pero hoy son honestamente `no_disponible`.
